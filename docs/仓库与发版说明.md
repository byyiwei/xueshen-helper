## 2. 版本号改哪里

用户能不能自动更新，只认脚本头的 `@version`。后端没有对外版本号。

每次发脚本，下面 **五处必须改成同一个新号**（例如 `5.3.6` → `5.3.7`）：

1. `scripts/xueshen-sc.js` 头部 `// @version`
2. `scripts/xueshen-gf.js` 头部 `// @version`
3. 两个脚本头部的 `@changelog`（写清这次改了什么）
4. `scripts/version.json` 里 `xueshen-sc` 和 `xueshen-gf` 的 `version`、`changelog`
5. `docs/script-intro.md` 的「🔄 更新日志」——加一节 `### vX.Y.Z (日期)`

第 5 处最容易漏：它不参与自动更新，所以漏了不会有人报错，只会让 GreasyFork 简介页的
日志停在旧版本（5.3.5/5.3.6/5.3.7 就这么连漏三笔，2026-09-20 才补齐）。

`version.json` 给脚本内部「发现新版本」提示条用。站点会读：

`https://xs.openget.cn/scripts/version.json`

油猴 / GreasyFork 读 GitHub raw：

- https://raw.githubusercontent.com/byyiwei/xueshen-helper/main/scripts/xueshen-gf.js
- https://raw.githubusercontent.com/byyiwei/xueshen-helper/main/scripts/xueshen-sc.js

**只改代码不改大版本号 = 用户不会更新。**

## 3. 改后端 / 网站 → 更新服务器（CNB）

改的是 `src/backend.py`、`src/database.py`、`static/`、`intro/` 等：

1. 在本仓库（CNB）提交并 `git push origin main`
2. 把文件拷到服务器 `/www/wwwroot/xs.openget.cn/` 对应路径
3. 重启后端（**实际是 supervisor 托管，不是 systemd**）：

```bash
# 程序定义：/www/server/panel/plugin/supervisor/profile/xs-backend.ini（MySQL 账号密码也在这里）
CTL=/www/server/panel/pyenv/bin/supervisorctl
$CTL -c /etc/supervisor/supervisord.conf restart xs-backend:xs-backend_00
$CTL -c /etc/supervisor/supervisord.conf status xs-backend:xs-backend_00
```

真实日志：`/www/server/panel/plugin/supervisor/log/xs-backend.out.log`（访问与业务日志）
与 `xs-backend.err.log`（异常栈）。`/tmp/xs-backend.log` 是历史手工进程留下的过期日志，别拿它判断现状。

只改后端 **不必** 推 GitHub，也 **不必** 改 `@version`。

### 代理商分销入口

| 角色 | 地址 | 说明 |
|------|------|------|
| 代理商门户 | `https://xs.openget.cn/distributor` | 用户中心侧栏「⚑ 代理商分销」也通向这里；用普通用户账号登录，token 存 `ne21_dist_token` |
| 平台后台 | `https://xs.openget.cn/admin` → ⚑代理商分销 | 代理商 / 卡密模板 / 批次与卡密 / 提现审核 / 分销配置 五页，接口前缀 `/admin/distributor/*` |

上线后 `admin_config` 里 `distributor_enabled`、`distributor_apply_enabled` 默认都是 `0`：门户会显示「分销渠道当前未开放」，接口一律 403。放开顺序建议是先只开总开关、自己在后台建档试跑，确认计价无误再开自助申请。注意 `distributor_default_discount` 默认 `1.0000`（等于不打折），放人进来之前先改成实际折扣。

### 代理商钱包：自助充值与提现

门户「钱包」页两件事，都走既有支付网关，不另起一套收银台。

**充值**（`POST /api/distributor/recharge`，10 次/10 分钟）

- 用合成套餐下单：`plan_type='dist_recharge'`、`id:0`、`business_type='代理商余额充值'`，
  所以 `/api/payment/plans` 这个公开接口不会把充值单暴露成可购买商品。
- 金额由服务端钳位：不低于 `distributor_min_recharge`、不高于 `RECHARGE_MAX = 20000`
  （`database.py`）。前端填多少不算数，改前端也刷不出便宜充值。
- 入账只发生在网关回调/轮询命中时：`_apply_distributor_recharge` 只在**加钱成功**后才把订单标 `paid`，
  失败会把订单退回 `pending` 让网关重推。**没有支付回跳页面加钱这条路**，前端拿不到入账口子。
- 充值单**不参与推广返利**（该分支在返利尾段之前就 return），也**不支持自助退款**：
  `refund_block_reason` 和 `/api/user/refund-preview` 都会拦住，要退只能管理员在后台处理。

**提现**（`POST /api/distributor/withdraw`，5 次/10 分钟）

- **申请即扣款**：提交那一刻金额就从余额划走，落到 `distributor_withdrawals`。
- 同一账号同时只允许一笔在途：靠 `uk_open(distributor_id, open_flag)` 唯一索引在数据库层兜住，
  不是靠应用层读一遍再判断。
- 后台点「已打款，通过」= 确认钱已经线下打过去了，**只关单、不再动余额**；
  点「驳回退款」才把余额退回，并记一条 `withdraw_reject` 流水。
- 开关在后台「分销配置」的 `distributor_withdraw_enabled`：关掉后门户提现按钮置灰、只显示历史，
  概览会提示「需要结算请联系管理员」。

后台「⚑代理商分销 → 提现审核」（`GET /admin/distributor/withdrawals`）负责审：
待审核/已打款/已驳回筛选、汇总条、收款二维码查看。侧栏「提现审核」角标是待审核笔数
（来自 `distributor_stats().wd_pending`）—— 钱在代理商点提交那一下就已经离开余额了，
压着不审就是欠账，所以这个角标不要忽略。

2. 提交到 **CNB**（源码备份）

GreasyFork 已配置从 GitHub 自动同步：

| 项 | 值 |
|----|----|

### 代理商「纯净版」：不落盘，按人现做

两份主脚本里埋了三类普通 JS 行注释哨兵，**官方版的字节行为零变化**：

| 哨兵 | 作用 |
|------|------|
| `// >>> FX-STRIP:<name>` … `// <<< FX-STRIP:<name>` | 渠道版整段删除（推广返利、QQ 频道、ScriptCat 更新条、自动更新检查） |
| `// >>> FX-INJECT:dist-channel` … | 渠道版用 `var __DIST = { shop, name, code }` 替换段内内容，官方版是三个空串 |
| 行尾 `// FX-CH:<name>` | 渠道感知表达式（店铺跳转、续费/价格链接、登录态参数、卡密激活、无店铺守卫共 7 处），构建时只校验不改动 |

构建与自检：

```bash
python3 scripts/check_script_parity.py     # 改过任一份主脚本必须跑到全绿
python3 scripts/build_distributor.py --channel 小明 --code D3 \
    --shop https://shop.example.com/buy --out /tmp scripts/xueshen-sc.js   # 手工出一份
```

代理商在门户「脚本」页点两个按钮各取一份（`GET /api/distributor/script?file=xueshen-sc|xueshen-gf`）：
仅 `approved` 可下载、按账号 10 次/小时、响应 `no-store`、文件名带渠道码、每次写一条 `script_event_logs`。

- **磁盘上不存在 `scripts/dist/`**：纯净版是每次请求现做的，所以 Nginx 不需要额外规则，
  但也因此**永远不要把构建产物提交进仓库**。
- 购买/续费跳转取自 `distributors.shop_url`（后台「编辑代理商 → 店铺链接」，或代理商在门户「脚本」页自助填；
  都走 `build_distributor.shop_url()` 同一套校验：必须 `https://` 开头、不含空格、≤255 字符，
  且**不许填官网自己的域名**（`openget.cn` 及其子域）——店铺写成官网等于替官网招客）。
  **留空时脚本内不出现任何购买入口**——不会再回落成官方页面链接（那等于渠道把客户送回官网下单），
  续费类入口整体置空并在原位提示「向渠道索取卡密，在「账号」面板输入卡密激活」；设置后 `FX-CH` 各处分改跳渠道店铺，
  价格页也不再带官方登录态参数。官方版 `__DIST.code` 恒为空串，守卫短路，行为零变化。
- **脚本里「用户中心 / 获取密钥」那一类链接不改**：渠道终端用户的脚本密钥仍在官网用户中心生成，
  链接置空会把人挡在门外。真正的收口做在账号上：用户激活过代理商卡密即 `users.channel='distributor'`
  （`src/database.py` 卡密激活时单向粘上，不覆盖人工纠正过的值），此后官网
  `/api/payment/purchase` 对其返回 403，
  `static/user.html` 同步收起套餐、支付方式、二维码与自有模型开通入口（剩余题数、到期时间、卡密激活原样保留）。
- **闲鱼自助建单/自确认两个口已下线**（`/api/payment/xianyu-create-order`、`/api/user/xianyu-confirm`）：
  它们让任意登录用户当场铸一张 `card_keys.source='xianyu'` 的未使用卡密并拿回明文码，
  再用普通卡密激活口即可 0 元兑换任意套餐；自确认口连"付款凭据"都不看，`xianyu_enabled` 也不参与判断。
  全仓（`static/*.html`、`scripts/*.js`）无一处调用，现行闲鱼流程是买家从店铺链接拿到在架卡密后自行激活，
  不经过这两个口。`database.py` 里的建单/激活函数暂留，重新接回界面前必须先有服务端可核验的到账凭据。
- **官方收银台地址在纯净版里只有一个合法出处**：挂着 `FX-CH` 的那一行（由渠道常量决定去留）。
  别处再写一遍 `xs.openget.cn/user?section=billing`，`build()` 直接 `BuildError`；
  `check_script_parity.py` 里有一发自检，专门确认这道门没被拆掉。
- **纯净版没有更新通道**：`@updateURL` / `@downloadURL` 与脚本内检查都被剥掉了。官方改版后不会推给
  已安装的用户，需要代理商回门户重新下载、自己通知客户替换。
- 头部的授权注释是水印，删得掉；真正可追溯靠 `card_keys.distributor_id` 和这条下载日志。

## 6. 自动更新怎么走

```
改脚本并提高 @version
    ├─ 拷到服务器 scripts/     → 站点下载、脚本内「发现新版本」条
    └─ push GitHub main        → GreasyFork 同步、油猴 @updateURL
```

开发始终在 CNB。GitHub 只是发布镜像。
