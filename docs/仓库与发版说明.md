# 仓库分工与发版说明

两套仓库、一台服务器。不要推错，也不要漏改版本号。

当前脚本版本：**5.3.5**

---

## 1. 用哪个仓库

| 仓库 | 地址 | 干什么 |
|------|------|--------|
| **腾讯云 CNB（开发主仓）** | https://cnb.cool/ipyiwei/XS | 后端、网站、脚本源码、文档。Cursor 里这个项目就是它。`git push` 默认推这里。 |
| **GitHub（脚本发布仓）** | https://github.com/byyiwei/xueshen-helper | **只放油猴 / GreasyFork / ScriptCat 自动更新用的脚本**，没有后端。 |

GitHub 里现在只应有：

- `scripts/xueshen-gf.js`（GreasyFork / 油猴同步源，路径不要改）
- `scripts/xueshen-sc.js`（ScriptCat / 油猴 `@updateURL`）
- `scripts/jdz-art-study-helper.user.js`
- `scripts/jiangxi-open-university-helper.user.js`
- `scripts/version.json`
- `README.md`、`.gitignore`

不要把 `src/`、`static/`、`config/`、`docs/` 再推回 GitHub。

---

## 2. 版本号改哪里

用户能不能自动更新，只认脚本头的 `@version`。后端没有对外版本号。

每次发脚本，下面 **四处必须改成同一个新号**（例如 `5.3.5` → `5.3.6`）：

1. `scripts/xueshen-sc.js` 头部 `// @version`
2. `scripts/xueshen-gf.js` 头部 `// @version`
3. 两个脚本头部的 `@changelog`（写清这次改了什么）
4. `scripts/version.json` 里 `xueshen-sc` 和 `xueshen-gf` 的 `version`、`changelog`

`version.json` 给脚本内部「发现新版本」提示条用。站点会读：

`https://xs.openget.cn/scripts/version.json`

油猴 / GreasyFork 读 GitHub raw：

- https://raw.githubusercontent.com/byyiwei/xueshen-helper/main/scripts/xueshen-gf.js
- https://raw.githubusercontent.com/byyiwei/xueshen-helper/main/scripts/xueshen-sc.js

**只改代码不改大版本号 = 用户不会更新。**

---

## 3. 改后端 / 网站 → 更新服务器（CNB）

改的是 `src/backend.py`、`src/database.py`、`static/`、`intro/` 等：

1. 在本仓库（CNB）提交并 `git push origin main`
2. 把文件拷到服务器 `/www/wwwroot/xs.openget.cn/` 对应路径
3. 重启后端：

```bash
systemctl stop xs-backend
# 若 8360 仍被占用：fuser -k 8360/tcp
systemctl start xs-backend
systemctl status xs-backend
```

服务名：`xs-backend`  
启动命令：`python3 /www/wwwroot/xs.openget.cn/src/backend.py`  
端口：`8360`

只改后端 **不必** 推 GitHub，也 **不必** 改 `@version`。

---

## 4. 改答题脚本 → 服务器 + GitHub 都要发

改的是 `scripts/xueshen-sc.js` / `xueshen-gf.js`：

1. **改大 `@version`**，同步 `version.json`
2. 提交到 **CNB**（源码备份）
3. 拷到服务器（用户立刻能下到，脚本内更新条也能读到新 `version.json`）：

```text
/www/wwwroot/xs.openget.cn/scripts/xueshen-sc.js
/www/wwwroot/xs.openget.cn/scripts/xueshen-gf.js
/www/wwwroot/xs.openget.cn/scripts/version.json
```

不需要重启 `xs-backend`（静态文件由 Nginx 直接提供）。

4. 再推到 **GitHub**（油猴 / GreasyFork 自动更新）。只推 `scripts/` 里的文件，不要把整个 CNB 仓库推进去。

GreasyFork 已配置从 GitHub 自动同步：

| 项 | 值 |
|----|----|
| 同步文件 | `scripts/xueshen-gf.js` |
| 分支 | `main` |
| Webhook | push 到 main 后触发（返回 403 可忽略） |
| 兜底 | 大约每小时再拉一次 GitHub |

ScriptCat 目前没有自动同步，`xueshen-sc.js` 仍要在 scriptcat.org 手动更一次（油猴走 `@updateURL` 仍会从 GitHub 拉）。

---

## 5. 一次发版检查清单

脚本发版：

- [ ] `xueshen-sc.js` / `xueshen-gf.js` 的 `@version` 已改大且一致
- [ ] `@changelog` 已写
- [ ] `scripts/version.json` 两个条目的 version / changelog / download_url 已改
- [ ] 已 `git push` 到 CNB：https://cnb.cool/ipyiwei/XS
- [ ] 服务器 `scripts/` 三个文件已覆盖
- [ ] 已 push 到 GitHub `main`：https://github.com/byyiwei/xueshen-helper
- [ ] 打开 raw 链接确认 `@version` 已是新号

只发后端：

- [ ] 已 push CNB
- [ ] 服务器对应文件已覆盖
- [ ] `systemctl restart xs-backend` 后 `is-active` 为 `active`，8360 在听

---

## 6. 自动更新怎么走

```
改脚本并提高 @version
    ├─ 拷到服务器 scripts/     → 站点下载、脚本内「发现新版本」条
    └─ push GitHub main        → GreasyFork 同步、油猴 @updateURL
```

开发始终在 CNB。GitHub 只是发布镜像。
