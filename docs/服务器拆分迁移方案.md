# 服务器拆分与迁移方案（2C2G 专职数据库 + 4C4G 应用机）

> 状态：方案待执行 | 编写日期：2026-10-22
> 目标：旧机只跑 MySQL 与备份，新机接管全部业务与公网入口。

## 一、先回答"宝塔能不能整个迁过去"

能，但不建议用"整面板迁移"。宝塔官方有「一键迁移」插件，可以把站点、数据库、证书、
计划任务一起搬走；但对我们这套情况有三个问题：

1. **它会连数据库一起搬**。我们的目标恰恰是数据库留在旧机，搬过去等于白搬一次 400MB 数据，
   而且旧机的 MySQL 还得继续活着，两边数据就分叉了。
2. **版本跨代**。旧机面板是 13.x 体系，新机现装的是 9.0-lts，插件与面板 API 不完全通用，
   一键迁移失败的概率不低，失败后现场难以还原。
3. **它会把不需要的东西也带过去**（PHP、FTP、Go 项目、Tomcat 模块等），新机应该保持干净。

结论：**面板本体新装，只迁移"站点配置 + 证书 + 站点文件"，数据库完全不迁。**

## 二、迁移分层表

| 层 | 内容 | 处理方式 |
|---|---|---|
| 面板本体 | 宝塔程序、安全入口、端口、BasicAuth | 新机全新安装（已在进行），不迁移 |
| 站点配置 | 5 份 nginx 站点 conf | 直接拷贝，纯文本，不依赖面板版本 |
| SSL 证书 | 5 个域名的证书目录 | 直接拷贝，免重签 |
| 站点文件 | `/www/wwwroot/*` 共 4.0 GB | 内网 rsync 全量同步 |
| 运行环境 | nginx、Node 22、Python 3.11、PM2、supervisor | 新机重装，不拷二进制 |
| Python 依赖 | sign/pdf 各自的 venv；xs 用系统级包 | venv 直接拷（路径一致可用）；xs 用清单重装 |
| 数据库 | 5 个业务库共 446 MB | **不迁**，留在旧机，应用改连 `10.1.0.6` |
| 计划任务 | 2 条宝塔 cron | 拷脚本 + 重建 crontab 行 |

站点体积实测：

```
sign.openget.cn    2.3 G   （frontend 2.1G 构建产物 + backend 199M 含 venv）
pets.openget.cn    798 M   （含 node_modules 186M）
pdf.openget.cn     497 M   （含 server/.venv）
openget.cn         396 M   （静态 console）
xs.openget.cn       37 M
合计               4.0 G
```

## 四、执行阶段

### P0 新机环境（30–40 分钟，不停机）

1. 宝塔面板安装完成，记下面板地址、账号、密码、安全入口；
2. 面板里只装 **nginx**，不装 MySQL / PHP / phpMyAdmin；
3. 装 Node 22、Python 3.11、PM2、supervisor；
4. 安全组：入站 22（限 IP）、80、443（TCP+UDP）、面板端口（限 IP）；
5. 预建 `/www/wwwroot/` 目录结构。

### P1 站点文件同步（20–40 分钟，不停机）

```bash
# 在旧机执行，推到新机内网
rsync -a --info=progress2 /www/wwwroot/ root@10.1.0.4:/www/wwwroot/
```

- 走内网，不受 6M 公网带宽限制；
- 先全量，P5 切换前再做一次增量（`--delete` 不需要，避免误删）。
- 校验：两端 `du -sh` 与关键文件 md5 对比。

### P2 站点配置与证书（15 分钟，不停机）

1. 拷 `/www/server/panel/vhost/nginx/` 下的 5 份站点 conf（排除所有 `.bak*`）；
2. 拷 `/www/server/panel/vhost/cert/` 下 5 个证书目录；
3. `nginx -t` 通过后 reload——此时新机已有 5 个站点，但没有服务在跑，
   访问会 502，属正常；
4. 注意三份 conf 里带 `listen 443 quic`，需要安全组放行 UDP 443，否则 nginx 启动报错可临时注释。

### P3 服务启动与守护（30 分钟，不停机）

| 服务 | 启动方式 | 关键改动 |
|---|---|---|
| xs 后端 | supervisor（沿用 `xs-backend.ini`） | `MYSQL_HOST=127.0.0.1` → `10.1.0.6` |
| sign 后端 | 现有 venv + 进程守护 | 数据库地址同样改内网 |
| pdf 后端 | `.venv/bin/uvicorn` 18700 | 数据库地址改内网 |
| pets / hub | PM2（`pm2 start` + `pm2 save`） | 数据库地址改内网 |

- venv 能直接复用的前提是**绝对路径保持一致**，所以必须装在 `/www/wwwroot/` 下；
- xs 用的是系统 python3.11 的全局包，新机 `pip install` 按清单重装（pymysql、DBUtils、
  aiohttp、APScheduler 等）；
- 顺手把明文写在 supervisor 里的数据库密码换成新密码。

### P4 内网验证（不停机）

在旧机执行，验证新机 5 个站点是否真的能出页面：

```bash
for h in xs.openget.cn openget.cn pets.openget.cn sign.openget.cn pdf.openget.cn; do
  curl -s -o /dev/null -w "$h -> %{http_code}\n" -H "Host: $h" http://10.1.0.4/
done
```

再逐项回归：登录、搜题、批量、题库工具、AI 生成、扣点、宠物端、签到端、PDF 工具。

### P5 DNS 切换（你操作，1–5 分钟）

1. 提前把 5 条 A 记录的 TTL 改成 300 秒（等 10 分钟让旧 TTL 过期）；
2. 把 A 记录指向 `123.207.5.245`；
3. 我这边盯 nginx 日志和 MySQL 连接，确认流量过来了；
4. 稳定 30 分钟后把 TTL 调回 600。

### P6 收尾（30 分钟）

1. 旧机停掉 5 个业务与 nginx（`systemctl stop nginx`）；
2. 旧机 MySQL buffer pool 512M → 1G（应用搬走后内存腾出）；
3. 每日 3:00 全库 `mysqldump` 传到新机，保留 7 天；
4. 监控：5 站点探针 + MySQL 连接数/慢查询；
5. 旧机安全组关闭 3306 / 8088 / 8360 / 8361 / 8362 公网入站，只留内网 3306。

## 五、风险与回滚

| 风险 | 影响 | 应对 |
|---|---|---|
| 迁移中某个服务起不来 | 该站点不可用 | 旧机未动，DNS 未切，用户无感 |
| DNS 切早了 | 用户访问到 502 | 记录改回去，TTL 300 秒生效 |
| venv 路径不一致 | Python 服务报找不到模块 | 保证 `/www/wwwroot/` 路径一致 |
| 4GB 文件传输中断 | 站点缺文件 | rsync 支持断点续传，重跑即可 |
| 数据库密码弱 | 安全风险 | 迁移时一并换强密码 |
| 旧机 MySQL 单点 | 数据库挂则全站挂 | P6 的每日备份必须在切换当天启用 |
