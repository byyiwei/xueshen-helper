## 二、关键发现：青书可以「接口直通」

这是 v2 最重要的结论，直接改变了方案。

### 学习不需要播放视频

青书的学习分是靠**接口上报的停留时长**累计的，跟播放器状态无关：

```
1. POST Student/Course/UploadStudyRecordBegin   → 拿到 recordId
2. 等 120 秒
3. POST Student/Course/UploadStudyRecordContinue  position += 120
4. 重复 2-3，每 5 次（10 分钟）重新读一次分数
5. 达标后 POST UploadStudyRecordContinue 带 end=true 关闭记录
```

参考脚本原话：**「青书按真实等待时间累计课件学习分数」**。

含义：
- 好消息：不用管倍速、不用防暂停、不用处理 Shadow DOM、不用管平台检测——这些坑全部绕开
- 坏消息：**省不了时间**，平台只认真实经过的时间，一节课件该等多久还是等多久

### 作业也不需要点页面

```
GET  Student/Course/AssignmentList         → HTML，解析出作业清单和 quizId
GET  Student/DetailData?quizId=            → JSON，直接拿到全部题目、选项、已有作答
POST Svc/SaveQuestionAnswer                → 按 questionId 逐题写答案
POST Student/ExercisePaper                 → 交卷
```

**题目是 JSON 返回的，不需要解析页面 DOM。** 也就是说 v1 里「必须让你发一段作业页 HTML」这个卡点，直接消失了。

## 三、青书接口清单（从参考脚本提取）

接口基址：`{origin}/{orgCode}`
- `origin` 例：`https://gaozhi.qingshuxuetang.com`
- `orgCode` 是 URL 第一段路径，例：`lzkjgzb`；取不到时参考脚本兜底用 `sntcm`

通用约定：

| 项 | 值 |
|---|---|
| 时间戳参数 | `_t`（每个请求自动加） |
| 请求头 | `X-Requested-With: XMLHttpRequest`、`Device-Trace-Id-QS: <随机设备ID>`、`Referer` |
| 鉴权 | **Cookie**，必须 `withCredentials: true` |
| 成功判定 | `hr === "0"` 或 `code === "0"` 或 `success === true` 或 `message === "成功"` |
| 限流 | 命中 429 后至少退避 10 秒，指数退避上限 120 秒 |

> 注意：鉴权走 Cookie，**`GM_xmlhttpRequest` 默认不带页面的 Cookie，必须用页面上下文的 XHR/fetch**。这是硬技术要求。

### 接口表

| 用途 | 方法 | 路径 | 参数 / 请求体 | 返回 |
|---|---|---|---|---|
| 课程列表 | POST | `Student/Course/CourseData` | 无 | JSON |
| 学习进度 | GET | `Student/Course/GetStudyRecordAndScore` | `teachPlanCourseId`, `periodId`, `_` | JSON |
| 成绩明细 | GET | `Student/Course/CourseScore` | `courseId`, `teachplanCourseId`, `_` | **HTML** |
| 作业清单 | GET | `Student/Course/AssignmentList` | `courseId`, `teachplanCourseId`, `teachPlanId`, `periodId`, `_` | **HTML** |
| 作业详情 | GET | `Student/DetailData` | `quizId` | JSON |
| 开始学习 | POST | `Student/Course/UploadStudyRecordBegin` | JSON：`{classId, courseId, contentId, contentType: 11, periodId, position: 0, detectId: null}` | `recordId` |
| 上报进度 | POST | `Student/Course/UploadStudyRecordContinue` | **multipart**：`{recordId, end, position, timeOutConfirm: "true"}` | JSON |
| 保存单题 | POST | `Svc/SaveQuestionAnswer` | JSON：`{quizId, questionAnswers: [{questionId, answer}]}` | JSON |
| 交卷 | POST | `Student/ExercisePaper` | JSON：`{quizId, quizType: "exercise", userQuizId, status: 2, timeSpend, questions: [{questionId, userAnswer, sequence}]}` | JSON |

### 字段说明

**课程对象**（`CourseData` 的 `data[]`）：

```
courseId, courseName,
teachingPlanCourseId / teachPlanCourseId / teachplanCourseId   ← 三个拼写都要兼容
teachPlanId（缺失时回退用 classId）, periodId,
learnStatus, learnStatusName（"已通过"）, score, allowLearn
```

**作业详情**（`DetailData` 的 `data`）：

```
data.userQuiz.userQuizId / score / statusName / submitTime / gradeTime
data.paperDetail.questions[]  （或 data.questions[]）
  └ questionId, description, typeDesc, options[], userAnswer, sequence
```

**答案格式**（关键）：

| 题型 | `typeN` | 写进接口的形式 |
|---|---|---|
| 单选 | `0` | 选项字母，如 `"A"` |
| 多选 | `1` | 选项字母拼接，如 `"ABD"`（无分隔符） |
| 填空 | `2` | 原文 |
| 判断 | `3` | 选项字母（不是"对/错"） |
| 简答/论述 | `4` | 原文 |

判断题目型 `3` 时，需要先把答案文本（对/正确/√/T）转成对应选项的字母——因为青书的判断题也是两个选项 A/B。

## 四、方案：主面板 + 接口直通模块

沿用 v1 的结论：**走主面板 `platformConfigs`**，平台 key 用 `qs`。

```js
{
  key: "qs",
  name: "青书学堂",
  domains: ["qingshuxuetang.com"],
  routes: qsRoutes,
  showAi: true
}
```

这样面板、日志、记录、答题、搜题、设置、配额全部现成。

### 路由表

```js
const qsRoutes = {
  match: [
    { keyword: "ExercisePaper", tab: "1", logic: qsAssignmentLogic },
    { keyword: "/Student/Course/CourseStudy", tab: "0", logic: qsCourseLogic },
    { keyword: "/Student/Course/CourseList", tab: "0", logic: qsCourseLogic },
    { keyword: "/Student/", tab: "0" }
  ],
  defaultRoute: { show: true, tab: "0" }
};
```

## 五、实施阶段（修订）

### 阶段一：接入 + 学习挂机

新增约 550 行：

1. 脚本头：`@match *://*.qingshuxuetang.com/*`、`@connect qingshuxuetang.com`
2. `qsContext()`：从 URL 抽 `orgCode / courseId / teachPlanId / teachPlanCourseId / periodId / nodeId`
3. `qsRequest()`：页面上下文 XHR + Cookie + 429 退避 + 串行排队
4. `qsCourseList()` / `qsProgress()` / `qsScoreDetail()`（后者解析 HTML）
5. `qsStudyLoop()`：begin → 每 120 秒 continue → 每 10 分钟读分 → 达标或超时 end
6. `qsCourseLogic`：面板上显示「当前分数 / 目标分数 / 已上报次数 / 位置」
7. 注册到 `platformConfigs`

**这一步做完就能挂课。**

### 阶段二：作业自动答题

新增约 500 行：

1. `qsAssignments()`：拉 `AssignmentList`，解析作业清单和 `quizId`
2. `qsAssignmentDetail()`：拉 `DetailData`，把题目转成**我们后端认识的格式**
3. 逐题调 `getAccurateAnswer()`（复用现有题库+AI，一分钱不额外花）
4. 答案格式转换：字母拼接 / 判断题转字母 / 填空原文
5. `qsSaveQuestion()`：逐题写回，写完回读校验
6. 交卷前整卷核对（题目数、每道题都有非空答案、userQuizId 未变）
7. 交卷 → 核对成绩

### 阶段三（可选）：讨论区

参考脚本有自动评论赚讨论分。这个功能有风险（发出去的内容是公开的、可能被老师看到），**建议不做**，或者只做「提示你去回复」，不自动发。

## 七、风险清单

| 风险 | 说明 | 应对 |
|---|---|---|
| **自动交卷不可撤销** | `status: 2` 一提交就是正式交卷，答案错了也改不回来 | **默认只保存不交卷**，交卷前在面板上明确确认（或做一个开关，默认关） |
| 接口是逆向出来的 | 青书升级前端可能改字段/路径 | 每个接口都做返回结构校验，异常时明确报错而不是静默失败 |
| 学习时长不能加速 | 平台按真实停留时间给分 | 面板上如实显示预计耗时 |
| Cookie 鉴权 | `GM_xmlhttpRequest` 不带 Cookie | 全部走页面上下文请求 |
| 429 限流 | 青书对并发敏感，参考脚本被限过 | 全局串行 + 指数退避，最小间隔 10 秒 |
| 作业重做 | 低于 60 分需要平台原生「重新答题」入口 | 未拿到重做链接时不自动重开，提示用户手动点 |
| 两份脚本同源 | 改一份必须同步另一份 | 改完跑 `check_script_parity.py` |
| 平台检测 | 接口直通比模拟操作更接近正常行为，风险反而更低 | 保持请求间隔自然 |
