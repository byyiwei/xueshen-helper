# 青书学堂（qingshuxuetang.com）接入方案

> 目标：让 `xueshen-gf.js` / `xueshen-sc.js` 支持青书学堂，复用现有题库 + AI 答题链路。
> 结论先行：**视频挂课可以马上做；作业/考试自动答题必须先拿到真实页面结构，否则只能靠猜。**

---

## 一、现有脚本架构（先搞清楚往哪接）

整套脚本是**一个 IIFE 包住三个东西**（`scripts/xueshen-gf.js:172` 起，到 `16627` 收尾）：

```
(function (vue, Antd, pinia, marked, rxjs, md5, DOMPurify) {
    // 1. 主面板   —— Vue3 + Antd + Pinia，超星 / 智慧树走这里
    // 2. 独立模块 —— o-learn.cn 景德镇，自带一整套实现
})();
```

### 1. 主面板：平台是「配置项」，不是 if/else

```js
// scripts/xueshen-gf.js:13693
const platformConfigs = [
  { key: "cx",  name: "超星学习通", domains: [...], routes: cxRoutes,  showAi: true  },
  { key: "zhs", name: "智慧树",     domains: [...], routes: zhsRoutes, showAi: false }
];
```

接入一个新平台 = **往这个数组加第三项**，不需要动任何 if/else。平台识别靠域名后缀：

```js
// 13629
hostname === domain || hostname.endsWith("." + domain)
```

路由匹配靠 URL 关键字，**先匹配到先用**：

```js
// 13816
const route = platformRoutes.match.find(item => url2.includes(item.keyword));
```

命中后设置面板默认标签页，并执行 `route.logic`：

```js
// 13842
const runRouteLogic = async () => {
  if (!route.logic || routeRunning) return;
  try { await route.logic(); } catch (e) { /* 写日志 */ }
};
```

### 2. 答题链路已经平台无关（这是最大的复用点）

```
业务逻辑
  └─ getAccurateAnswer(question)              // 3014 行
       └─ callLocalBackendAnswer(question)    // 2904 行
            └─ POST https://xs.openget.cn/api/v1/cx
```

`question` 对象只需要这几个字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `title` | string | 题干（可含 HTML，图片会被自动抽出来转 base64） |
| `optionsText` | string[] | 选项文本数组 |
| `type` | string | 题型码：`0` 单选 / `1` 多选 / `2` 填空 / `3` 判断 / `4` 简答 / `6` 论述 … |
| `refer` | string | 来源 URL |
| `element` | Element | 可选，用于从 DOM 抓图片 |

返回值：

```js
{ code: 1, data: { answer: [], src: "bank|cache|ai|pick", multimatch, candidates, remainCount }, msg }
```

**青书只要能把页面上的题目翻译成这个对象，题库、AI、相似题手动选择、计数、限流重试全部免费复用。**

### 3. 答题处理器是「基类 + 子类」结构

```js
class BasicQuestionHandler {           // 7923 行
  this.parseHtml = () => { throw "请用子类重写" };
  this.fillQuestion = () => { throw "请用子类重写" };
  this.questionType = { "单选题": "0", "多选题": "1", ... };   // 题型中文名 → 题型码
  this.removeHtml = (html) => { ... };                        // HTML 洗成纯文本
}

class QuestionHandler$1 extends BasicQuestionHandler { ... }  // 8177 行，超星
class QuestionHandler2   extends BasicQuestionHandler { ... }  // 10320 行，智慧树
```

青书只需要写 **第四个类**：`QsQuestionHandler`，实现 `parseHtml`（抓题）和 `fillQuestion`（填答案）。

### 4. 视频引擎已经有一套成熟实现，可以照搬

`o-learn.cn` 独立模块里（`14767` 起）有完整的视频处理栈，而且是纯函数、不依赖主面板的 Pinia store，改造成本低：

| 能力 | 位置 | 说明 |
|---|---|---|
| 倍速设置 | 15031 `applySpeed` | 同时写 `playbackRate` 和 `defaultPlaybackRate` |
| 倍速劫持 | 15062 `hijackPlaybackRate` | 改写 `playbackRate` 的 setter，网页想改倍速会被还原 |
| 倍速锁 | 15045 `startSpeedLock` | 每秒校一次 |
| 拦截暂停 | 15102 `hijackPause` | 网页调用 `pause()` 直接拦掉；用户自己点暂停则放行 |
| 自动播放 | 15120 `autoPlayVideo` | 静音起播 → 起播后取消静音，失败重试 10 次 |
| 视频检测 | 15947 | 带 Shadow DOM 穿透 |
| 自动下一节 | 15256 | 播完进下一节 |

**这套东西比参考脚本的 `video.playbackRate = 0.5` 高一个数量级，直接搬，不要参考那套。**

### 5. 双版本：改一份必须同步另一份

`xueshen-sc.js`（脚本猫）和 `xueshen-gf.js`（油猴/Greasy Fork）是**同一套代码 + 不同的依赖装载方式**：

- sc 版用 `@require https://xs.openget.cn/libs/...`
- gf 版用 `@require https://cdn.jsdelivr.net/...`，并把字体映射表内联（所以大 694KB）

`scripts/check_script_parity.py` 会校验两份主体是否同源（忽略 `@require/@resource/@updateURL/@downloadURL` 和字体表）。**加平台必须两个文件都改，改完跑一次这个脚本。**

## 二、参考脚本能提供的信息（已提取）

参考脚本（用户提供的 `青书.txt`）技术含量不高，但把青书这个站摸了一遍，下面这些是**可信的**：

### 域名与租户

```
https://www.qingshuxuetang.com/           主站
https://gaozhi.qingshuxuetang.com/lzkjgzb/  各学校独立子域 + 路径前缀
```

租户 = **URL 第一段路径**（上例是 `lzkjgzb`）。

```
接口基址 = origin + "/" + 第一段路径
```

主站 `www` 下的 `MyQingShu` 路径不适用（参考脚本里直接 return）。

### 课程列表接口

```
POST {origin}/{租户}/Student/Course/CourseData
Content-Type: application/x-www-form-urlencoded
鉴权：Cookie 里的 AccessToken（无需额外 header，浏览器自动带上）

返回：
{
  "message": "成功",
  "data": [
    { "courseName": "...", "score": 23, "courseId": 4, "teachPlanId": 21,
      "periodId": 12, "classId": 29, "learnStatus": 2 }
  ]
}
```

- `score` 是进度百分比
- `learnStatus === 2` 表示**未完成**

### 课程页 URL 规律

```
{origin}/{租户}/Student/Course/CourseStudy?courseId=&teachPlanId=&periodId=&tabType=study
{origin}/{租户}/Student/Course/CourseStudy?courseId=&teachPlanId=&periodId=&tabType=homework
{origin}/{租户}/Student/Course/CourseStudy?courseId=&teachPlanId=&periodId=&tabType=score
```

（`classId` 可选，有就带上）

### 视频页

同一个 CourseStudy 地址，后面多一个 `cw_nodeId`：

```
...&cw_nodeId=kcjs_1
```

- 页面里有原生 `<video>`
- 播完靠改 `cw_nodeId` 的数字部分跳下一节：`kcjs_1` → `kcjs_2`；多层的是 `kcjs_1_2` → `kcjs_1_3`

### 作业/考试页

```
URL 含 ExercisePaper
题目容器：.question-detail-container      （元素的 id 属性就是题目 ID）
题干：    .detail-description-content
标题区：  .quiz-title
```

### 目录页 DOM（备用方案）

```
#currentCourseDiv .col-md-3 a            课程条目
  └ p > span                             [名称, 进度]
.content-area .title span                课程名称
#currentCourseDiv .col-sm-12             含「结束时间：」
```

### 红线：参考脚本里的盗号代码，一个字都不搬

```js
// 青书.txt:27-63  登录成功后把账号密码明文 POST 到 http://81.70.42.96:2099
url: `${main_hosts}/insertOrderInfo`,
data: `account=${username}&password=${password}`,
```

以及它的答题接口（`/queryAnswerById`，拿题目 ID 问它自己的服务器）也不接入——我们用自己的题库 + AI。

## 三、方案：走主面板，不走独立模块

可以参考脚本那样单起一个独立模块，但**不推荐**：

| 方案 | 复用 | 代价 |
|---|---|---|
| 主面板 `platformConfigs` 加一项 | 面板 UI、日志、记录、答题、搜题、设置、配额、版本提示，全部现成 | 要在两份脚本里加路由和逻辑函数 |
| 独立模块（照 o-learn 那样） | 只复用后端接口 | 登录、配额展示、日志面板、设置面板全部重写一遍，约 1860 行 |

**推荐：主面板方案，平台 key 用 `qs`。**

```js
{
  key: "qs",
  name: "青书学堂",
  domains: ["qingshuxuetang.com"],
  routes: qsRoutes,
  showAi: true
}
```

## 四、分阶段实施

### 阶段一：接入 + 视频挂课（信息足够，现在就能做）

**新增内容**

1. 脚本头：加 `@match *://*.qingshuxuetang.com/*`、`@match *://qingshuxuetang.com/*`
2. 脚本头：加 `@connect qingshuxuetang.com`
3. `qsRoutes`（约 30 行）

```js
const qsRoutes = {
  match: [
    { keyword: "tabType=homework", tab: "1", logic: qsHomeworkLogic },
    { keyword: "ExercisePaper",    tab: "1", logic: qsExamLogic },
    { keyword: "cw_nodeId",        tab: "1", logic: qsVideoLogic },
    { keyword: "CourseStudy",      tab: "0", logic: qsCourseLogic },
  ],
  defaultRoute: { show: true, tab: "0" }
};
```

4. `qsVideoLogic`（约 180 行）
   - 等 `<video>` 出现（含 Shadow DOM 扫描）
   - 套用 o-learn 那套视频引擎：倍速劫持 + 拦截暂停 + 自动播放重试 + 倍速锁
   - 监听 `ended`，按 `cw_nodeId` 递增跳下一节
   - `location.replace` 前把状态写进 `GM_setValue`（青书是整页跳转，不是 SPA）

5. `qsCourseLogic`（约 80 行）
   - 用租户拼出 `CourseData` 接口地址
   - 拉课程列表，把「未完成（learnStatus === 2）」的课写进日志面板，点一下能跳过去

6. 注册：`platformConfigs` 加一项（2 行）

**不改动**：后端、题库、AI、任何现有平台代码。

### 阶段二：作业/考试自动答题（需要真实页面）

**卡点：参考脚本里作业/考试的填答代码是被注释掉的**（原文 454-466 行），它只抓了题干和题目 ID 去问自己的题库，**没有一行「点选项、填答案、提交」的实现**。

也就是说这些选择器**全部未知**：

- 选项元素（label / input / 自定义 div？）
- 单选/多选框怎么点（原生 `input` 还是 Element UI 组件）
- 题干里的题型标识怎么读
- 提交按钮
- 判断题的「对/错」按钮
- 填空题的输入框

硬猜的结果是：**脚本跑起来了，日志刷得很漂亮，实际上一个选项都没点中，还白扣答题次数。**

**所以阶段二开始前，需要你提供一份真实作业页的 HTML**：

> 打开青书任意一个作业页 → F12 → 用元素选择器点中「一道题的整块」→ 右键 → Copy → Copy outerHTML → 贴给我

一段就够，我能从里面反推出全部选择器。

拿到之后新增：

1. `QsQuestionHandler extends BasicQuestionHandler`（约 350 行）
   - `parseHtml`：遍历 `.question-detail-container`，抓题干、选项、题型
   - `fillQuestion`：按题型点击/填写
2. `qsExamLogic` / `qsHomeworkLogic`（约 200 行）
   - 复用 `getAccurateAnswer` → 填 → 提交
   - 相似题手动选择、跳过模式、自动提交，全部沿用现有 `QuestionHandler2` 的逻辑（可以照抄再改选择器）

## 六、风险清单

| 风险 | 影响 | 应对 |
|---|---|---|
| 青书作业页选择器未知 | 阶段二无法开工 | 等真实 HTML |
| `cw_nodeId` 递增法只对连续同级视频有效 | 遇到跳级、非视频节点、多层目录会断 | 阶段一先跑，断了再改成读左侧目录树（需要目录 DOM） |
| 青书是整页跳转（MPA） | 状态丢失、每页重新注入 | 关键状态写 `GM_setValue` |
| 视频可能在 iframe 内 | 拿不到 `<video>` | 视频检测要扫 iframe 和 Shadow DOM（o-learn 那套已支持） |
| 倍速被平台判定异常 | 封号 / 不给进度 | 参考智慧树的教训（v5.5.2 钳制 1.8x），青书先给 1.5x 上限 |
| 青书接口靠 Cookie，GM_xmlhttpRequest 不带 Cookie | 课程列表拉空 | 用页面内 `fetch` 而不是 `GM_xmlhttpRequest` |
| 两份脚本不同步 | 用户更新后一半人坏 | 改完跑 `check_script_parity.py` |
| Greasy Fork 2MB 限制 | gf 版现在 1.43MB，加 60KB 仍安全 | 无 |
